# Decisione

1. **Libreria dal lockfile in un clone nuovo**: `tools/restore_library.R` installa `renv` nella libreria vuota del progetto dai binari Posit PPM (Ubuntu noble), ripristina `renv.lock` e controlla ogni versione. È il comando d'installazione del README. `tools/S1.6_env_check.R restore` resta per il controllo dell'ambiente di S1.6.
2. **La batteria dello Step 1 gira solo sul server del laboratorio**. In un clone nuovo `tools/link_server_inputs.sh` collega dalla copia di lavoro del server ogni percorso ignorato da git (esclusi libreria, log, cache). Per le cartelle vere crea la cartella e collega i suoi elementi, perché le regole di `.gitignore` con la barra finale non valgono per un link. Alla fine controlla che `git status` del clone sia vuoto. Il README e CLAUDE.md lo dicono; la riproducibilità fuori dal server è BL-181.
3. **Design v1.9: solo annotazioni** datate «[v1.9, S1.6b: ...]» nei sette punti in cui il testo era rimasto indietro rispetto al codice o a decisioni già prese (intestazione, decisione 1, §4.6, §5.1, §5.2 passo 5, §8, riga di v1.7 dello storico), nello stile già usato dal design; nessun testo cancellato, nessun comportamento nuovo.
4. **README e CLAUDE.md del 2025** spostati con `git mv` in `docs/legacy/` con una riga in testa che dice da cosa sono superati; `docs/legacy` esente nel controllo OKF.
5. **Controllo dei documenti** (`tools/S1.6b_doc_check.py`): un percorso si scrive per intero dalla radice del repository (un nome senza cartella è ambiguo e non passa); dopo la revisione avversariale il controllo legge anche i file inclusi nel dossier.

# Motivazione

(1) Nella prima prova in clone nuovo lo script di ripristino di S1.6 non poteva partire: carica `renv` dalla libreria del progetto, che in un clone non esiste. Con `tools/restore_library.R` il ripristino ha richiesto 0.2-0.3 minuti, con 0 pacchetti diversi su 199, in tre prove.
(2) Nella prima prova la batteria si è fermata nel test di S1.5d, che legge le maschere di R2 escluse da git, e senza `.venv`. Nella seconda, con i link alle cartelle, `git status` mostrava le cartelle collegate come non tracciate e la protezione di `R/testing/run_S1.5.sh` si fermava. Nella terza, con i link ai contenuti, la batteria è passata con i soli FAIL noti in 2 122 s. Versionare gli input non è ragionevole adesso (`.venv` 6.6 GB, nuclei di R2 76 MB, più circa venti percorsi assoluti del volume dati citati dai test), e i test sono in `R/`, che questo step non tocca[^probes].
(3) Riscrivere sezioni del design è una scelta di Luca; allineare il testo a decisioni già registrate no, e le annotazioni lasciano leggibile la storia.
(4)-(5) Provenienza e precisione: un controllo che accetta nomi ambigui non distingue un documento giusto da uno vecchio.
